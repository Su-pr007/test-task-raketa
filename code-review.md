## По файлам
### Контроллеры
[AddToCartController](./src/Controller/AddToCartController.php)
- Переименовать `get` на `add`, чтобы больше соответствовать названию класса;
- В методе `get` ожидается любой класс, реализующий `RequestInterface`. Вместо этого стоит использовать `JsonResponse`, у которого должен быть реализован метод для получения данных сразу в формате массива. Тогда внутри метода не нужно будет использовать функцию `json_decode`, которая ещё и может выбросить исключение;
- После получения данных из запроса, нужно провести валидацию данных. В проекте не вижу классов, предназначенных для этого, поэтому предполагаю, что достаточно будет простой проверки на существование нужных данных в массиве;
- Контроллеры не должны заниматься конкретными действиями с сущностями, а только передавать их в сервисы;
- Нет проверки на нахождение товара.

[GetCartController](./src/Controller/GetCartController.php)
- Не используется переменная `$request`;
- Вынести формирование ответов, чтобы упростить метод.

[GetProductsController](./src/Controller/GetProductsController.php)
- В `ProductsView` изменения, поэтому меняем способ формирования ответа. Сначала запрашиваем данные из репозитория, затем передаём во View;
- Вынести формирование ответов, чтобы упростить метод.

### Репозитории
[CartManager](./src/Repository/CartManager.php)
- Не понятно почему репозиторий наследуется от `ConnectorFacade`, и почему управляет подключением к бд;
- Указать типы данных для переменных, значений, возвращаемых методами;
- В методе `saveCart` перепутаны местами аргументы, передающиеся в `set`;
- В `getCart` неправильно создаётся корзина, в случае, если её нет в редисе. Что именно там нужно сделать я не знаю, так что вынес создание в пустой метод;
- `getCart` пытается получить значение из redis, но только в случае ошибки пишет лог, и пытается создать пустую корзину. Если в redis пустое значение, метод вернёт это пустое значение. Переделать, чтобы корзина создавалась в том случае, если в redis нет корзины.

[ProductRepository](./src/Repository/ProductRepository.php)
- try-catch более трудозатратная задача для php, чем обычная проверка на null, поэтому стоит переделать метод `getByUuid`, чтобы соответствовать этому замечанию;
- В методе `getByCategory` в sql запросе возвращается только `id`, а для создания сущности товара нужно гораздо больше колонок (`id`, `uuid`, `is_active`, `category`, `name`, `description`, `thumbnail`, `price`).
